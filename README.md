# Трип-агент Островка (трек «AI-агент для путешествий и отелей»)

AI-агент, который превращает одно сообщение путешественника («хочу к тёплому морю в ноябре, недорого, с ребёнком, без долгих перелётов») в готовую поездку: задаёт только необходимые вопросы, предлагает направления с погодой, ценой «под ключ» и временем в пути, собирает и сравнивает 3 пакета «перелёт/поезд + отель + трансфер», объясняет выбор и компромиссы, проверяет состыковки, пересобирает план при изменении условий и доводит до (имитированной) оплаты. После покупки умеет ранний заезд, перенос дат с пересчётом, трансфер, напоминания (.ics) и отмену, а ещё помнит предпочтения между сессиями.

- 🎬 Видео-скринкаст: **TODO — вставить ссылку перед сдачей** (Яндекс.Диск / Google Drive, доступ по ссылке)
- 🌐 Развёрнутый сервис: не развёрнут (опционально)

> **Честно о данных.** API и данных Островка у нас нет. Все отели, рейсы, поезда, трансферы и цены — **синтетические**, генерируются детерминированно (одинаковый запрос → одинаковый результат). Справочник из 33 направлений (климат по месяцам, визы, правила для питомцев, районы, достопримечательности) собран вручную по открытым источникам и усреднён. Оплата и бронирование **имитируются**. На шаге оплаты интерфейс прямо пишет, что деньги не списываются; о синтетических данных говорим на демо.

## Быстрый старт

```bash
git clone <URL репозитория>
cd <repo>
docker compose up --build
# открыть http://localhost:8080
```

Сборка занимает ~1–2 минуты (образ ~210 МБ). Ручных доустановок нет. Файл `.env` необязателен: без него агент полностью работает на встроенном разборе русского языка. С LLM (любой OpenAI-совместимый API) понимание свободного текста устойчивее и агент знает любое место мира.

### Запуск с LLM (для жюри)

Ключ для жюри лежит в репозитории только в зашифрованном виде — `secrets.env.age`. Расшифруйте его в `.env` и запустите как обычно:

```bash
age -d -i <ваш_закрытый_ключ.txt> -o .env secrets.env.age
docker compose up --build
```

В логе контейнера появится `Trip agent started. LLM: on (<модель>)`. Если LLM недоступна или упёрлась в лимит, агент сам переключается на запасную модель, а затем на встроенные правила — сервис не падает.

| | |
|---|---|
| Провайдер | **OpenRouter** (OpenAI-совместимый API), `LLM_BASE_URL=https://openrouter.ai/api/v1` |
| Модель | **`google/gemma-4-31b-it:free`**; запасные — `nvidia/nemotron-3-super-120b-a12b:free`, `nvidia/nemotron-3-ultra-550b-a55b:free` |
| Ключ | отдельный ключ OpenRouter, созданный только для жюри |

`.env` для жюри: `LLM_BASE_URL=https://openrouter.ai/api/v1`, `LLM_MODEL=google/gemma-4-31b-it:free,nvidia/nemotron-3-super-120b-a12b:free,nvidia/nemotron-3-ultra-550b-a55b:free`.

**Почему так.** Агенту от LLM нужно две вещи: разобрать русскую фразу в JSON с параметрами поездки и выдать «карточку» любого места мира (координаты, аэропорт, климат по месяцам). Бесплатные модели OpenRouter иногда упираются в лимит запросов (HTTP 429), поэтому моделей несколько: при ошибке агент сам переходит к следующей, а у рассуждающих моделей «мысли» отключаются (`reasoning.effort=low`, `exclude`), чтобы ответ приходил быстро. Если недоступны все модели, агент продолжает работать на встроенных правилах — сервис не падает. Подойдёт и другой OpenAI-совместимый провайдер (например, cloud.ru Foundation Models): достаточно поменять `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL` в `.env`.

### Запуск без Docker

```bash
pip install -r requirements.txt
python run.py
```

`run.py` берёт LLM из `.env` и перед запуском делает один пробный запрос: понятно сообщает, если ключ не подходит, кончился баланс или неверно указана модель, и ставит первой ту модель, что отвечает. Если в `.env` ключа нет, спросит ключ (ввод скрыт), адрес API и модель прямо в терминале — такой ключ живёт только в памяти процесса и нигде не сохраняется; Enter на вопросе о ключе — запуск без LLM. `python run.py --ask` — ввести ключ в терминале, даже если он есть в `.env`; `--visible` — если в терминале не работает вставка в скрытое поле.

## Зависимости и переменные окружения

Рекомендованные ресурсы: **1 CPU, 512 МБ RAM** (в простое ~60 МБ). Внешние сервисы не требуются.

- Python 3.12 + FastAPI/Uvicorn (один контейнер `app`, порт 8080, процесс под непривилегированным пользователем `app`)
- SQLite в docker volume `agent-data` (`/data/agent.db`) — сессии, память пользователя, брони, события метрик
- LLM — опционально, через OpenAI-совместимый API

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_PORT` | `8080` | порт на хосте (внутри контейнера всегда 8080) |
| `LLM_API_KEY` | пусто | ключ OpenAI-совместимого API (секрет: только в `.env` / `secrets.env.age`); пусто — работа только на правилах |
| `LLM_BASE_URL` | пусто | адрес OpenAI-совместимого API: cloud.ru `https://foundation-models.api.cloud.ru/v1`, OpenRouter `https://openrouter.ai/api/v1`, DeepSeek `https://api.deepseek.com/v1`, Ollama `http://localhost:11434/v1` |
| `LLM_MODEL` | пусто | имя модели у выбранного сервиса |
| `LLM_TIMEOUT` | `30` | таймаут запроса к LLM, сек; при ошибке агент тихо откатывается на правила |
| `LLM_ENABLED` | `true` | `false` — выключить LLM, не удаляя ключ |

| `TELEGRAM_BOT_TOKEN` | пусто | секрет; если задан — тот же агент работает в Telegram (long polling) |

| `LOG_LEVEL` | `INFO` | уровень логов (всё пишется в stdout: `docker compose logs app`) |

## Сидирование

Данные генерируются на лету — отдельная загрузка не нужна, всё работает сразу после `docker compose up`. Чтобы наполнить дашборд метрик результатами тестового набора:

```bash
docker compose exec app python -m eval.run_eval      # или: make seed
# либо отдельным сервисом после healthcheck приложения:
docker compose --profile eval up eval
```

## Маршруты / доступ

- `/` — веб-интерфейс (чат + панель «Что я понял» + «Ход мыслей агента»), адаптивен под мобильные
- `/health` — `200 OK`, `{"status": "ok"}`
- `POST /api/session` — новая сессия (`{"user_id": "..."}` — чтобы агент «вспомнил» пользователя)
- `POST /api/chat` — ход диалога: `{"session_id", "user_id", "message"}` или `{"action": {...}}` (кнопки UI)
- `GET /api/bookings?user_id=` — мои поездки; `GET /api/bookings/{id}/ics` — напоминания в календарь
- `GET|DELETE /api/profile/{user_id}` — память агента / «забыть меня»
- `GET /api/metrics` — метрики живых сессий и тестового прогона; `POST /api/eval/run` — прогнать тестовый набор
- Тестовых учётных данных нет: пользователь идентифицируется анонимным id в браузере (localStorage)

Пример без UI:

```bash
curl -s -X POST localhost:8080/api/chat -H 'content-type: application/json' \
  -d '{"message":"Хургада в декабре на неделю вдвоём"}' | python3 -m json.tool | head -40
```

## Что умеет агент — по задачам трека

| Задача | Как реализовано |
|---|---|
| **1. Понимание и уточнение** | Разбор 30+ типов слотов: даты («с 10 по 17 ноября», «на майские», «зимой», «в конце августа», «на выходные»), состав и возраст детей, питомцы, бюджет (в т.ч. «на человека», «100к»), город вылета vs направление, страны и исключения («не Египет»), лимит перелёта, поезд, питание, отмена, звёзды, приоритеты. Скрытые требования: «с ребёнком» → детский клуб и без adults-only, «недорого» → приоритет цены, «без долгих перелётов» → ≤5,5 ч, «недалеко на выходные» → ≤3 ч. **Уточняет только критичное** (когда; возраст детей) одним сообщением, остальное — разумные допущения, которые видны и правятся в панели. На 22 тестовых сценариях — **0,09 уточнения на сценарий**. |
| **2. Вдохновение** | Ранжирует 33 направления каталога (плюс места со всего мира от LLM): погода в выбранный месяц (воздух, море, дожди, сезонные риски — тайфуны, муссоны), время в пути из вашего города, визы, бюджет **под ключ по реальным (синтетическим) ценам**, совпадение с интересами, удобство с детьми/питомцем. Сам выбирает самые выгодные даты в месяце. Показывает, кого и почему исключил. Для размытых запросов — разные типы отдыха. Антарктиду и Северный полюс понимает как поездку до «ворот» — Ушуаи и Мурманска, откуда уходят экспедиционные круизы, — с пояснением про сезон и сам круиз. Если без LLM просят место вне каталога («Париж», «Сейшелы»), честно говорит об этом и предлагает ближайшие по духу направления. |
| **3. Подбор и сравнение** | Отели, перелёты (прямые и с пересадкой, лоукост с докупкой багажа), поезда РЖД, трансферы (такси, шаттл, индивидуальный с детским креслом, аэроэкспресс, катер/гидросамолёт на Мальдивах). Сравнение не только по цене: отмена, питание, до моря/центра, время трансфера, ночные вылеты, пересадки, совместимость дат. Три пакета: **Оптимальный / Экономный / Комфорт**. |
| **4. Объяснение** | Для каждого пакета: «почему подходит», «чем пожертвовали», «риски»; формула взвешивания (цена/отель/дорога/трансфер) видна и переключается («что важнее») — карточки пересобираются на месте, без лишних сообщений в чате. Таблица «почему не другие» и честно отсеянные отели («adults only», «шумный район — не для малышей»). Панель «Ход мыслей агента» показывает каждый вызов инструмента. |
| **5. Сборка и покупка** | Корзина с выбором тарифа и трансфера, допами (страховка, ранний заезд/ночь до заезда, поздний выезд), план по дням, повторная проверка состыковок, форма путешественников, имитация оплаты, номер брони. |
| **6. Пересборка** | «на два дня позже», «бюджет меньше», «с нами едет собака», «нас будет трое», «без пересадок», «из Екатеринбурга», «вместо Хургады Шарм», «без трансфера» → агент пересчитывает только затронутое, сохраняет выбранный отель, если он ещё подходит, и показывает **дифф** «что изменилось» (даты, отель, рейсы, итог ±). Если условие ломает направление (собака → Бали, где ввоз запрещён) — объясняет и предлагает альтернативы. |

**Параметры можно задать и формой.** Панель «Что я понял» — это редактируемая форма: откуда, куда (пусто — подобрать), даты или месяц с числом ночей, взрослые и возраст детей; бюджет, питомца и пожелания агент берёт из диалога. Она заполняется тем, что агент понял из диалога; после «Применить» агент сразу показывает подходящие направления или пересобирает поездку с диффом.

**Проверка состыковок** (независимый модуль `planner.check_connections`): заселение в день прибытия с учётом часовых поясов и ночных перелётов (прилёт «на следующий день»), ранний прилёт → ночь накануне или ранний заезд, поздний прилёт, ночной обратный вылет → выезд накануне без оплаты лишней ночи, длинное ожидание между выездом и рейсом → поздний выезд, часы работы шаттла и гидросамолёта, детские кресла, короткие пересадки, загранпаспорт/визы, правила для питомцев.

### Любое место мира (через LLM)

В ручном каталоге 33 направления с выверенными данными. Любое другое место агент узнаёт у LLM: из запроса «хочу в Рейкьявик», «на Крит», «в Италию», «в Антарктиду» модель возвращает **карточку места** — координаты, аэропорт, климат по месяцам, море, районы для проживания, что посмотреть, сезонные риски. Агент проверяет карточку (диапазоны, формат), сверяет визы, прямые рейсы и уровень цен со своим справочником стран (`app/data/world_meta.py`) и превращает её в обычное направление: дальше работают тот же подбор отелей и рейсов (если прямых рейсов из России нет — с пересадкой в Стамбуле, Дубае или Белграде), проверка состыковок, корзина и оплата.

- **Подбор «куда поехать» тоже идёт по всему миру**: на запрос без конкретного места («северное сияние в феврале», «море в ноябре с детьми») LLM предлагает до 5 мест со всего мира, агент получает их карточки и сравнивает вместе с каталогом по одним правилам (погода, дорога, визы, цена под ключ).
- **Каталог — это проверенные данные, а не ограничение**: для 33 направлений климат, районы и цены выверены вручную, поэтому они используются вместо догадок LLM; если LLM подставляет похожее по написанию направление каталога («Антарктида» → «Анталья»), агент это отсекает.
- **Страна или регион** («Италия», «Европа», «Карибы») → модель предлагает 3–4 конкретных места, агент сравнивает их как обычные направления.
- **Антарктида и Северный полюс** → поездка до «ворот» (Ушуая, Мурманск) с пояснением: туда ходят только экспедиционные круизы, сезон, длительность и порядок цены; вне сезона агент предупреждает. Работает и без LLM.
- **Недостижимое место** (космос и т. п.) → агент честно говорит, что туда не продаются туры, и предлагает реальные варианты.
- Карточки кэшируются в SQLite: повторный запрос того же места не тратит токены.
- Без ключа LLM агент работает на каталоге: о месте вне каталога честно сообщает и предлагает ближайшие по духу направления.
- Цены, наличие и состыковки всегда считает сам агент, LLM даёт только сведения о месте.

### Дополнительные задачи

- **После покупки:** ранний заезд (по политике отеля: гарантирован/по запросу/недоступен → ночь до заезда; агент сам замечает, если ранний заезд не нужен), поздний выезд, перенос дат с котировкой (сборы за обмен билетов, штраф отеля, разница в цене) и подтверждением, трансфер к купленному отелю, напоминания + экспорт в календарь (.ics), отмена с расчётом возврата.
- **Память и персонализация:** город вылета, состав и возраст детей (если сказать «с ребёнком» — возраст подставится из памяти без вопроса), предпочтения отмены/приоритета, прошлые поездки, данные путешественников для автозаполнения. «Забыть меня» — в разделе «Память».
- **Метрики качества:** тестовый набор из 22 сценариев с симулятором пользователя и независимыми проверками брони (`eval/`), дашборд «Метрики» в UI и `GET /api/metrics` по живым сессиям.
- **Мобильная версия и мессенджер:** адаптивная вёрстка (панель плана — выезжающая шторка), Telegram-бот на том же агенте (`TELEGRAM_BOT_TOKEN`), карточки → компактный текст, подсказки → inline-кнопки.

## Архитектура

```
 Браузер (vanilla JS, без сборки)        Telegram (опционально)
        │  /api/chat {message | action}          │
        ▼                                        ▼
 ┌──────────────────────── FastAPI (app/main.py) ──────────────────────┐
 │ agent.py — оркестратор хода:                                        │
 │   1. parse   nlu.py (правила, RU) ──┐ + llm.py (опц., JSON-слоты,   │
 │                                     │   валидация, откат на правила)│
 │   2. update  слоты запроса, что изменилось                          │
 │   3. decide  уточнить │ вдохновить │ собрать │ пересобрать │ корзина│
 │              │ оплата │ пост-продажа                                │
 │   4. act     planner.py → инструменты inventory.py                  │
 │   5. explain почему / компромиссы / риски / дифф                    │
 ├─────────────────────────────────────────────────────────────────────┤
 │ planner.py: rank_destinations · pick_dates · build_plan (3 пакета)  │
 │             score_hotel/transport · check_connections · itinerary   │
 │ inventory.py: search_flights · search_trains · get_hotels ·         │
 │               price_hotel · search_transfers (детерминированно)      │
 │ data/: 33 направления (климат, визы, питомцы, районы), 10 городов   │
 │ store.py: SQLite — сессии, память, брони, события │ metrics.py      │
 └─────────────────────────────────────────────────────────────────────┘
```

**Почему гибрид, а не «LLM сама вызывает инструменты».** Цены, наличие, даты и состыковки считает детерминированный планировщик — LLM не может выдумать отель или ошибиться в дате заселения. Язык понимают правила (работают офлайн и мгновенно, ~20 мс до рекомендации) и, если подключена, LLM, чей JSON валидируется по белому списку значений. Так агент воспроизводим, его легко тестировать, а при недоступности LLM он не ломается.

**Политика решений агента:**
- спрашивает, только если без ответа нельзя посчитать цену/погоду (когда ехать; возраст детей; откуда — если едете в Москву); всё остальное — допущение с пометкой в панели;
- раз уж спрашивает — объединяет вопросы в одно сообщение с готовыми ответами-кнопками, «Неважно, подбери сам» — всегда доступно;
- если направление названо — сразу собирает пакеты; если нет — предлагает 3–4 направления с объяснением;
- при изменении условий — пересобирает, сохраняя закреплённые пользователем компоненты, и показывает дифф;
- перед оплатой ещё раз прогоняет проверку состыковок и не даст оформить пакет с ошибкой.

## Сценарий для демо (5 минут)

1. «Хочу к тёплому морю в ноябре, недорого, с ребёнком, без долгих перелётов» → агент задаёт **один** вопрос (возраст ребёнка), остальное берёт допущениями — видно в панели «Что я понял».
2. Ответ «5 лет» → 3 направления с погодой, ценой под ключ и временем в пути; ниже — кого исключил и почему (Пхукет — 10 ч лёта).
3. «Выбрать» фаворита → 3 пакета, объяснения, проверка состыковок; раскрыть «Сравнить отели».
4. «А если на два дня позже?» → дифф: отель тот же, рейсы и итог пересчитаны.
5. «С нами едет собака» → остаются только отели и рейсы, где можно с животными; для Бали агент отказал бы и предложил альтернативы.
6. «Почему этот отель?» → формула весов, плюсы/компромиссы/риски, отсеянные отели; переключить «Что важнее».
7. «Беру оптимальный» → корзина (тариф, трансфер, допы), «Оформить» → имена → «Оплатить» → номер брони и напоминания.
8. После покупки: «Ранний заезд», «Перенести на 2 дня позже» (котировка → подтверждение), скачать .ics.
9. «Новая поездка» → агент помнит город, состав и возраст ребёнка. «Метрики» → «Прогнать тестовый набор».

## Тесты и линтер

```bash
make test        # pytest: разбор языка, планировщик и чекер состыковок, полный путь до брони, память, LLM-слой
make lint        # ruff
make eval        # тестовый набор сценариев в контейнере
```

CI (`.github/workflows/ci.yml`): ruff, pytest, прогон тестового набора, `docker build` и smoke-проверка `/health`.

## Ограничения прототипа

- Инвентарь синтетический: названия отелей и номера рейсов вымышлены, авиакомпании и цены — модельные.
- Курортные сезоны и климат — усреднённые нормы, не прогноз погоды.
- Оплата, подтверждения отелей и уведомления — имитация (без реальной отправки писем/SMS).
